# TableCfg 数据提取与分析

目标是得到可复查的“源表 → 字段 → 关联键 → 业务含义 → 展示或计算”链路，区分数据存在、字段可解释、业务算法已确认这三个层次。

## 范围与入口

- 先识别当前仓库、数据源和用户要求的分析/实施模式。查找或解释数据默认只读；请求使用本 skill 不等于授权修改页面、发布或写回源表。
- 在 AKEDatabase 中，以仓库 `AGENTS.md` 和 `skills/akedatabase-development/SKILL.md` 为流程维护源。`public/TableCfg/**`、`public/Json/**` 是只读输入；验证和版本管理遵循仓库要求，不因本 skill 自动运行审计、浏览器或测试。
- 通常从 `public/TableCfg` 取本地样本。数据历史可能位于独立的数据仓库；网站中的 gitignored 文件没有提交记录，不代表游戏中没有历史数据。先确认用户的数据仓库位置与版本，再查询历史。
- 针对后勤技能参数、数值筛选或线索概率，按需读 [后勤技能案例](references/spaceship-skills.md)。其他业务不必加载该案例。
- 针对档案、对话顺序、地区归属、LevelData/LevelScriptData 索引或新增/修改误标，读 [文本关联、索引与版本差分](references/narrative-analysis.md)。

## 定位数据而不是猜数据

1. 用 `rg --files` 找业务相关表名，再用 `rg` 搜字段、明确的实体 ID 和引用键。文件名只用于找候选，不证明表的用途或归属。
2. 同时查看已有模块的数据适配器、加载表清单、详情转换和素材路径。代码是现有使用方式的证据，不是游戏语义一定正确的证明。
3. 先读少量完整记录，确认顶层对象/数组、键与 `id` 的关系、数组结构及空值形式。随后按影响结论的字段分组查看变体，不只凭第一条样本下结论。
4. 记录数据快照：本地路径、已知版本或数据仓库提交。不要把网站 `appversion` 当作游戏数据版本。

按问题扩大范围。例如“后勤数值在哪里”先看角色技能关联与技能表的 `parameters`，不先全盘扫描图片或解析全部 Json；只有收录审计才需要有范围说明的全量盘点。

从已知文字反查时，先在对应语言文本表定位精确文本 ID，再以完整 ID 找引用它的业务字段；从已知实体 ID 出发时，先正向展开外键，再用反向引用核对使用者。搜索命中是候选证据，应读取所在记录的完整结构和字段路径，不能把一次字符串命中当作精确关联。

### 提取与覆盖检查

- 先限定问题的计量单位：表行、实体、交互物、对话段、文本行与文件数量分别统计；一个文件可含多个交互物，一个对话可被多个交互物引用。
- 对需批量处理的任务，用保留整数精度的解析器一次读取相关表，在内存中建立主键/反向引用索引；避免逐条重复读取大型文本表。只读字段聚合与运行项目测试分别说明，遵守当前任务的验证边界。
- 提取结果保留来源路径、记录键、字段路径、引用目标和解析状态；显示名称与首句可变，不能用作稳定身份。只报告命中摘要与必要样本，避免输出整张大表。
- 验证规律时主动找反例：缺失/空/零值、重复身份、一对多引用、未知枚举、不同结构签名、无法解析的命名和孤立记录。抽样只能支持样本结论；“全部符合”必须说明枚举全集和未能读取的部分。
- 审计“尚未使用的表”时，分别检查静态表名、动态加载、共享适配器及聚合表的间接覆盖。未搜到表名不等于未收录；聚合表与分表也不能直接重复计数。
- 统计空间时注明是源文件逻辑字节数、磁盘占用还是传输大小，说明单位。不要把一份包含其他内容的 LevelData 文件大小全部解释成目标文本净占用。

## 建立真实关联

对每条关联记录：起始实体、源字段、目标表/键、关系基数、缺失处理。

```text
角色表键
  → 角色技能表[角色键].skillList[].skillId
  → 技能表[skillId]
  → parameters / effectType / roomType / 文本引用
```

- 优先用显式外键。名称相同、ID 前缀相近、图标相同、表顺序相邻，都不能单独证明关联。
- 不同表中的同值枚举不自动等价；例如技能效果类型与舱室属性类型需要独立确认映射。
- 枚举主表的真实记录，保留一对多和多对多关系。固定 ID 白名单只适用于用户明确限定的页面范围，不应变成数据模型的全部收录范围。
- 去重使用稳定业务身份和语义：如角色、技能栏位、技能 ID、解锁条件；不要按显示名称去重，避免丢失等级或不同来源。
- 覆盖报告区分已关联、明确排除、缺少引用、未关联记录、未知枚举和结构异常；“零条记录”不能代替“加载失败”。

## 文本、整数与参数

### 本地化文本

- 名称/描述常是 `{ id, text }`；`text` 为空时，通过 `I18nTextTable_<语言>[id]` 读取。不能把空 `text` 当作无描述。
- 文本 ID 可能是有符号 Int64。保留精确整数/字符串键；不要先交给 JavaScript `Number` 再试图恢复。Python 整数、经确认保留 Int64 的 PowerShell 解析可用于只读分析。
- 不要对 JSON 全文用简单数字正则替换：必须避开字符串、转义、浮点和指数写法。优先使用能保留整数精度的解析方式。
- 若接入 AKEDatabase 页面，复用 `AKEV3.table`、`AKEV3.text` 和现有富文本渲染；不要另建文本加载管线。

### 结构化数值

- 先找 `parameters`、属性、等级表和常量，再考虑文本。用于筛选、排序和计算的数值优先来自结构字段；描述用于核对语义，不用正则抓出第一个数字当成强度。
- 查看参数的 `realType`、`valueType` 及 `valueFloatList`、`valueIntList`、`valueBoolList`、`valueStringList` 等容器，确认类型、参数位置、列表长度和单位。
- `0` 和 `false` 是合法值，不用 `||` 把它们当作缺失。数值 `2` 可能是枚举、数量或档位，不应一律乘以 100。
- 同一参数可能在多个容器中有重复表示。避免重复计入；按已确认类型读取，出现冲突时报告。字符串形式如 `0.30000000000000004` 可能是序列化痕迹，不能据此断言额外精度。
- 比例到百分比的转换要有语义依据。保留源值供计算，显示时按合理精度格式化；不要把显示舍入误当成游戏计算规则。
- 参数结构或枚举未适配时，保留记录和可识别描述，标记数值不可用并记录诊断，不填零冒充已解析。

## 核对含义与证据边界

对每种影响功能的参数签名，交叉核对：

- 同技能不同等级是否遵循相同位置和单位；
- 同效果不同角色是否一致；
- 各作用对象的参数是否对应类型表、配方、物品或线索表；
- 中文或其他已提供文本是否与结构参数一致；
- 常量数组是否有显式索引关系、调用方或运行逻辑证明。

结论使用三种强度：

| 证据 | 可表述的结论 |
| --- | --- |
| 字段和外键直接存在 | “表中存储了数值/引用，可以读取” |
| 多条记录、文本与关联表一致 | “当前数据核对得到此映射，作为有来源的适配约定” |
| 仅名称、数组长度或数值相似 | “候选解释，仍需调用逻辑确认” |

配置值存在不等于算法已知：概率与权重、加算与乘算、叠加上限、触发条件和最终结算需要额外证据。没有证据时，可做同类档位比较，不输出未经证明的最终概率或收益。

## 用于筛选与页面时

- 分开组织源记录、标准化数据与 UI。标准化项至少保留来源身份、效果类型、作用对象、原始数值、单位、等级和解析状态。
- 筛选选项由实际记录与真实类型表生成；固定枚举映射须注明来源、适用快照及未知值行为。
- 排序先明确可比范围：同类效果、同类作用对象、同单位。概率档位不能与生产百分比混排。
- 按角色合并行时，明确排序取匹配技能的最高值、最低值还是其他业务聚合；不要把互斥等级求和。无关技能可保留展示，但不能进入匹配技能的评分。
- 依用户需求决定按钮、下拉框、搜索和默认排序；不要将某一次 UI 选择写成所有任务的规则。
- 素材优先读取表内 `icon`/`iconId`，参考已有模块已证实的路径规则或资产索引。找不到图片时保留文字，不凭相似文件名猜图标用途。
- 新增表依赖或条目归属后，按项目约定同步搜索索引、路由、诊断及受影响资源版本。原始数据、数值适配与显示规则应能分别追溯。

## 交付

按任务复杂度提供：关键源表及可点击路径、关联链、参数含义和单位、代表性记录、已确认/推断/未确认部分，以及对筛选或计算的实际限制。

说明做了哪些只读分析或代码修改，以及有没有运行验证。读取 JSON、聚合字段和静态查看差异不能表述为浏览器功能验证通过。
