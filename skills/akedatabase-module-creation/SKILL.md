# 创建 AKEDatabase 模块

目标是交付可由现有导航、数据加载和搜索体系访问的模块，而非孤立的 HTML 页面。

开始前读取 [项目开发规范](../akedatabase-development/SKILL.md)。它是权限、只读数据、样式、版本与验证规则的维护源；本文件仅补充模块创建方法。用户当前要求优先，不将某个旧模块的特殊设计套用为全站规则。

## 确定模块边界

- 从当前任务确定展示对象、用户操作、条目粒度和明确排除的内容。数据表的存在不代表应把它单独做成模块；与现有页面属于同一对象时，先判断是否适合新增详情区或子视图。
- 查阅当前分支、工作区改动、`plugin/manifest.json`、`version.json`，选择唯一且稳定的模块 ID。导航 ID、HTML 根节点、控制器、版本与搜索条目应使用一致标识。
- 结合用户要求和邻近模块确定导航位置、标题、图标与可见性。没有明确要求时沿用最相近新模块的约定并在交付说明，不把隐藏或公开作为所有新模块的固定默认。
- 确定条目 ID 的业务含义。单一实体通常沿用源 ID；混合对象可使用 `kind:id`，但必须记录解析方式并让页面、搜索与跨模块链接一致。不要用数组下标、排序位置或本地化名称作为稳定 ID。

## 先建立数据契约

涉及游戏数据时读取 [TableCfg 分析方法](../tablecfg-analysis/SKILL.md)，确认主表、关联表、键、文本引用、枚举、数值单位和素材字段，再写展示逻辑。

- 按真实记录枚举条目，并保留来源表与来源键。定义收录条件、缺失关联和未知类型的处理，不复制示例中的实体白名单。用户明确限定的页面范围属于业务范围，应同时反映到搜索解析中。
- 建立“源记录 → 规范化条目 → 详情”的转换。列表、筛选、统计、搜索尽量复用同一语义；不要各自猜测关联或用显示文本反解数值。
- 取数使用现有 `AKEV3.table` 等公共入口；查看其当前失败、缓存和本地化约定，不另写并行加载管线。必需表失败不能伪装成零条目；可选数据缺失也要与请求或解析失败区分。
- 无法确认的字段保留诊断，不用猜测补齐。数据层保留 ID 与来源，不等于普通界面可以直接展示技术信息。

## 选择现有接入方式

先阅读最相近模块的 HTML、实际加载脚本及公共实现，再决定是否新增脚本。下面是定位入口，不是需要整份复制的模板。

| 场景 | 优先参考 | 判断要点 |
| --- | --- | --- |
| 数据目录、搜索列表与详情 | `plugin/spaceship.html`、`plugin/js/ake-catalog.js` | 使用共享 `AKECatalog.mount`，由业务脚本提供数据转换与详情 |
| 已有对象的独立数据范围 | `plugin/monument.html`、`plugin/js/v3-table-data.js`、`plugin/js/v2-dungeon.js` | 复用既有适配器与渲染器；不要因模块名不同就复制整套业务代码 |
| 特殊交互子视图 | `plugin/js/spaceship-skills.js` 及其调用处 | 通过详情挂载与清理接口接入，独立管理交互状态 |

这些文件包含各自的业务特例。例如帝江号的固定舱室范围、颜色与图标规则不应自动成为新模块的要求；旧页面中遗留的专属布局也不优先于公共组件。

采用 `AKECatalog` 时，阅读当前 `mount` 实现，确认 `tables`、`primary`、`build`、详情渲染及可选 `mountDetail` 的实际语义与回调签名。不要仅凭字段名推断必需表行为或复制过时调用。

HTML 应是由路由加载的页面片段，按依赖顺序加载公共数据脚本、共享组件和业务脚本。目录布局复用 `ake-ui-directory`；遵循组件使用的 `data-catalog-*` 标记。保留移动列表的打开、关闭与遮罩结构，避免只实现桌面侧栏。

## 界面与生命周期

实现界面前读取 [页面风格统一](../akedatabase-ui-style/SKILL.md)，按页面用途选择目录、详情或工具结构，并查阅对应组件来源。

- 复用 `AKEUI`、已有 `ake-ui-*`、文本解析、物品卡片和链接组件。样式授权与三主题规则见项目开发规范；新增模块本身不表示授权新增 CSS。
- 界面文案放入 `public/CH/i18n.json` 和 `public/EN/i18n.json` 的合适命名空间，优先复用已有公共键。游戏名称和描述仍读文本表，不复制到界面语言文件。
- 图标从源字段和已知资产路径取得，沿用现有资源地址处理。缺图和空名称提供可读回退；不能只按猜测的文件名生成大量失效链接。
- 明确加载中、合法空列表、无匹配结果、缺失条目和加载失败的显示。筛选应改变实际数据集合，排序使用语义一致的原始值，不比较格式化文本。
- 使用稳定条目 ID 恢复选择与处理深链。无匹配深链应走现有未找到流程，不悄悄选中第一项造成“跳转成功”的错觉。
- 非富文本内容转义，富文本复用现有解析器；不要直接把原始字段拼入 HTML。
- 将页面监听器、详情监听器、异步请求、定时器与临时视图绑定到正确生命周期。详情切换时释放上一个详情，模块销毁时清理资源；迟到的异步结果不能覆盖新条目或已离开的页面。复用组件已有清理能力，不重复注册全局监听器。
- 隐藏技术信息遵循当前 `showHidden` 设置，设置变化后不能残留先前显示的 ID、原始字段或调试徽章。某项数值是否属于普通内容依据产品需求决定，不能机械照搬其他模块的徽章限制。

## 完成系统接入

按实际变化维护以下接点；不是每个模块都必须新增全部文件。

| 接点 | 要完成的内容 |
| --- | --- |
| `plugin/<module>.html` | 页面片段、根标识、依赖顺序与移动端结构 |
| `plugin/js/` | 新业务转换或复用适配器；必要的挂载、选择和释放能力 |
| `plugin/manifest.json` | 唯一 `id`、标题键、`contentFile`、位置及适用的图标/可见性字段 |
| `public/CH/i18n.json`、`public/EN/i18n.json` | 导航及模块界面文案，保留占位符语义 |
| `plugin/js/search-index.js` | 实际用到的主表、关联表和代码来源，包含动态依赖 |
| `plugin/js/search-data.js` | 根据命中字段、记录键和真实关联生成模块与条目 ID |
| `version.json` | 按项目规范更新实际受影响的模块、脚本及资源版本 |

搜索清单仅表示候选归属；必须另行确认命中内容是否确实在该条目中展示。公共表可能关联多个模块，保留一对多结果。没有可靠关系时提供可识别候选或诊断，不伪造精确跳转。确认跨模块链接的目标粒度，例如关卡 ID 不一定就是关卡模块使用的系列 ID。

优先通过现有注册与外部脚本接入，避免为了加导航而修改首页。确需改变公共组件时追踪其他调用方与缓存版本，不把只服务单一模块的业务常量塞入公共工具。

## 交付边界

通过读取修改文件与 Git 差异检查接点是否遗漏、是否保留用户改动。默认不运行测试、构建、语法检查、服务器或浏览器；用户另行授权后只执行授权范围。

交付说明模块入口与可见性、数据覆盖范围、复用方式、版本变化及已知未确认关联。列出与此次功能有关的手动验收点，例如导航进入、直接深链、切换详情、搜索筛选、手机列表、语言/主题切换和隐藏信息开关。未运行的检查明确标注，不把静态检查说成页面验证通过。

仅创建或维护本 skill 不更新网站版本；实际模块开发的版本与发版操作遵循项目开发规范。
